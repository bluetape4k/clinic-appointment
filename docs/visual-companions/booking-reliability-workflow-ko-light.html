예약 신뢰성 업무 흐름

고객 원문을 복제하지 않고 typed 예약 결과와 병원별 정책 snapshot으로 새 예약의 자격을 설명 가능하게 판단합니다.

시뮬레이션 · 한 건의 결정

1

신뢰된 event

NO_SHOW 또는 CANCELLED를 책임 enum과 source version으로 수신합니다. 이름·전화번호는 경계를 넘지 않습니다.

2

유효 정책

tenant 기준과 clinic override를 합성한 immutable snapshot을 고정합니다. 기본 lookback 180일, threshold 3건, cooling-off 24시간입니다.

3

bounded history

clinic·member 범위에서 최대 100행을 읽고 같은 event ID는 가장 높은 source version만 남깁니다.

4

순수 evaluator

고객 책임 사건만 no-show와 late cancellation으로 합산합니다. 병원·운영·미확정 책임은 제한 수에서 제외합니다.

5

immutable decision

판정, count, reason code, 최대 32개 trigger ID, expiry와 SHA-256 digest를 저장합니다.

6

예약 gate

OFF는 기존 흐름, SHADOW는 관측, ENFORCE는 새 가예약·신규 확정만 제한합니다.

ELIGIBLE

활성 threshold 미만이거나 직원 override가 유효합니다. 자동 제안 후보로 진행합니다.

REQUIRES_STAFF_APPROVAL

병원 설정이 직원 승인 모드이면 자동 당일 제안 대신 검토 큐로 보냅니다.

RESTRICTED

자동 당일 제안에서 제외합니다. 이미 CONFIRMED인 예약은 변경하지 않습니다.

STALE / UNAVAILABLE

정책 snapshot·저장소를 신뢰할 수 없으면 ENFORCE에서 fail-closed 하고 correlation ID만 남깁니다.

결정 이력 · 왜 이렇게 동작하는가

B 선택

PROPOSED와 HELD는 재평가하지만 기존 CONFIRMED는 유지합니다. 신규 직접 확정은 commit 직전에 같은 gate를 확인합니다.

개인정보 경계

회원 DB의 원문을 복제하지 않고 opaque MemberId만 전달합니다. 직원 설명은 allowlist reason과 bounded ID로 제한합니다.

대규모 clinic 보호

한 건 조회 상한, trigger cursor, DB lease, idempotency digest, backoff와 clinic allowlist로 재평가 폭증을 제어합니다.

롤백

V17은 additive입니다. readiness가 실패하거나 canary 기준을 넘으면 allowlist를 비우고 SHADOW 또는 OFF로 내립니다.
