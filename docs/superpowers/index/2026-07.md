가예약·병원 승인·고객 동의·자원 점유를 하나의 확정 약속 생명주기로 관리한다.
관리자 직접 확정과 고객 가예약을 분리하고, 확정 변경은 고객 동의와 수정불가한

## 2026-07-30: 프로필 변경 기반 진행 중 예약 재평가

**What**: CRM 프로필 변경 시 진행 중인 `PROPOSED`와 `HELD` 예약만 비동기로
재평가하고, `CONFIRMED` 예약과 유효한 기존 선점은 유지하는 구현 계획이다.
최신 revision 병합, clinic 공정 처리, 제한된 페이지, 처리 시점 assessment 조회,
원자적 선점 교체, dry run과 점진 활성화를 함께 다룬다.

**Why**: 모든 예약을 즉시 다시 계산하면 대형 병원의 backlog가 전체 worker를
독점할 수 있고, 확정 예약이나 유효한 선점을 자동으로 바꾸면 환자에게 이미 약속한
진료를 훼손할 수 있다. CRM 원본 정보까지 예약 시스템에 복제하면 개인정보 관리
범위도 불필요하게 넓어진다.

**Key files**:

- `docs/superpowers/specs/2026-07-30-profile-change-reservation-reevaluation-design.md`
- `docs/superpowers/plans/2026-07-30-profile-change-reservation-reevaluation-plan.md`

**Verification plan**: H2·PostgreSQL·MySQL migration과 동시성, stale revision과
lease 복구, 개인정보 비보존, 100 clinic·10,000 active reservation에서의 공정성과
p95 처리 목표, 한국어·영어와 light·dark 시각 자료 계약을 구현 단계에서 검증한다.
